# AGENTS.md

Guide for coding agents and people working in this repository. The rules in full: [CONTRIBUTING.md](CONTRIBUTING.md); what the project is: [README.md](README.md).

## What this is

`nyra-base` is the base image of Nyra OS: a Debian system, built with mkosi, delivered as an atomic image with bootc. It holds the recipe, the boot chain, the update daemon and the tests that try to break it. What it builds boots on users' machines.

## Map (read in this order)

1. `README.md`, then `docs/BOOT.md`, `docs/UPDATES.md`, `docs/LESSONS.md` (why things are as they are).
2. `mkosi/mkosi.conf`, `Containerfile`: the root file system and the bootc layer.
3. `files/usr/`: what is copied into the image. Configuration goes in `/usr`, never in `/etc`.
4. `ci/`: scripts and checks CI runs (`ci/precheck.sh` is the list of offline checks).
5. `tools/`: `vm/` (guest and VM tests), `install/` (installer script), `signing/`, `titanic/`, `sbom/`, `iso/`, `hooks/`.
6. `updated/`: `nyra-updated`, the update daemon (Rust). `ntpd-rs/`, `zlib/`, `pam-totp/`: other projects built into the image, pinned. `patches/upstream/`: our patches to other projects.
7. `.github/workflows/`: what runs where.

## Build, test, lint

- Before every push: `ci/precheck.sh`. About 40 s; it runs shellcheck, actionlint, the offline self-tests of `ci/` and `tools/`, and a secret scan. `ci/precheck.sh --list` shows the checks, `--only ID` runs one. Missing tools run from pinned container images (podman); a check that cannot run prints `SKIPPED` and fails the run. Never read SKIPPED as a pass. If the machine-interface check fails once with other test runs active, run it again, then find the cause.
- Rust, in `updated/`: `cargo fmt --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo test --locked --workspace`, `cargo audit`.
- CI only (need KVM, an arm64 runner, cloud keys or 20 to 60 minutes): the image build, boot, update and encryption tests, the Titanic battery, the SBOM gate, signing and publishing. Rehearse a guest script offline first (a `--self-test`, stubs, a user namespace) and say in the pull request what only the VM run proves.
- Enable the local guard once: `git config core.hooksPath tools/hooks` (it refuses a push to `main` and runs `ci/precheck.sh`).

## Working rules

- Work on a branch, never on `main`. One small, focused change per pull request, with a clear reason.
- Before you start, read the recent changes (`git log`) and the docs of the area.
- Commit messages: a short imperative subject in plain English. The only trailer is `Co-Authored-By: <model name> <noreply@anthropic.com>`. No "Generated with ..." line and no session link in commits or pull request text.
- A test that fails sometimes is a bug: find the cause, do not rerun until green. Never weaken or skip a test to make it pass.
- Pin what CI runs: actions by commit SHA, container images by digest, packages by version or hash.
- English for code, comments, commits and docs. New files start with an SPDX header (`GPL-3.0-or-later`).

## Code rules (KISS: code a person can read)

- Read top to bottom. Functions about 50 lines at most, files short. Each file starts with a short header saying what it does and why it exists.
- Comments explain why, not what.
- Shell, Python, container files: one thing per script, `set -euo pipefail`, shellcheck clean (`-S warning`), no clever one-liners.
- Rust: plain `match` and loops instead of long iterator chains; no macros; no generics, explicit lifetimes or `dyn` unless needed, with the reason next to them; no new `unsafe` (the one existing call in `updated/` has a `SAFETY` comment).
- A dependency that makes the code clearer is fine; do not write your own to avoid one without a reason.
- No options or layers "for later".

## Security-sensitive areas

Changes here need a security review before merge: the boot chain and Secure Boot (`docs/BOOT.md`), signing and release jobs (`tools/signing/`, `docs/SIGNING.md`, the sign and publish jobs in `.github/workflows/`), disk encryption, the update daemon and its signature checks (`updated/`), authentication (SSH, `pam-totp`), the installer script, and the SBOM gate. Never put secrets, keys or tokens in the repository, tests or logs; test keys are generated by the test and deleted. Report vulnerabilities privately: [SECURITY.md](SECURITY.md).
